# multiagent-orchestrator

An AI agent orchestration service for the full product lifecycle: business analysis,
Jira breakdown (Epic and User Stories), manual QA, and Playwright test automation
generation.

The system takes a single task (for example, `Run the full cycle for http://site.local`),
runs it through the selected **skills** in sequence, and at each stage automatically
decomposes the work into subtasks, executes them in parallel, and compiles a final report.

## What it is for

- **Automated pipeline** from requirements to automated tests with a single request.
- **Skills** — workflow scenarios (markdown files in `skills/`); each defines its phases,
  agent prompts, and result aggregation rules.
- **Planner → workers → aggregator**: the planner splits a stage into independent
  subtasks, workers execute them in parallel, the aggregator compiles a single report.
- **Agent tools**: fetching website content by URL, running PowerShell commands, and
  creating Jira issues via the REST API.
- **Result persistence**: all reports and the generated autotests project are written to
  `results/<timestamp>/`.

## Skills

| ID                  | Purpose                                                            |
| ------------------- | ------------------------------------------------------------------ |
| `business-analysis` | Business analysis of a website/product and requirements            |
| `jira-scope`        | Epic and User Stories, creating issues in Jira                     |
| `manual-qa`         | Test plan, test cases, defects, QA report                          |
| `aqa-playwright`    | Playwright autotest generation and execution                       |
| `seo-audit`         | SEO audit: technical, on-page, performance                         |

## Requirements

- Node.js 20+
- Access to an OpenAI-compatible API (OpenAI, OpenCode Go, Gemini, Ollama, etc.)

## Installation

```
npm install
```

## Configuration

Configuration lives in `.env`.

```ini
PLANNER_PROVIDER=openai
PLANNER_MODEL=
PLANNER_BASE_URL=
PLANNER_API_KEY=sk-...

WORKER_PROVIDER=openai
WORKER_MODEL=
WORKER_BASE_URL=
WORKER_API_KEY=

AGGREGATOR_PROVIDER=openai
AGGREGATOR_MODEL=
AGGREGATOR_BASE_URL=
AGGREGATOR_API_KEY=

CONCURRENCY=1
```

To create issues in Jira (`jira-scope`), add:

```ini
JIRA_BASE_URL=
JIRA_EMAIL=
JIRA_API_TOKEN=
```

Create the token in Jira: Profile → Security → API tokens.

## Usage

Run an explicit chain of skills (recommended):

```
npm run dev -- --skills=business-analysis,jira-scope,manual-qa,aqa-playwright "Run the full cycle for http://example.com: business analysis, epic and user stories, manual qa and autotests"
```

All skills:

```
npm run dev -- --skills=all "Your task text"
```

The selected chain and the results directory are printed at startup:

```
Skills: business-analysis -> jira-scope -> manual-qa -> aqa-playwright
Results dir: \results\
```

Build and run the compiled version:

```
npm run build
npm start
```

## Results

```
results/<timestamp>/
├── task.md                 # task and selected skills
├── summary.md              # consolidated report across all stages
├── autotests/              # Playwright project generated by the agent
└── <skill-id>/
    ├── final.md            # final stage report
    └── subtasks.md         # results of all subtasks
```

The `results/` directory is listed in `.gitignore`.

### Running the generated autotests

```
cd results\<timestamp>\autotests\autotests
npx playwright test --headed
```

`--headed` opens the browser window (Playwright runs headless by default). If the browser
is not installed: `npx playwright install chromium`.

## Architecture

| File                   | Responsibility                                                |
| ---------------------- | ------------------------------------------------------------- |
| `src/index.ts`         | CLI, skill selection, result persistence                      |
| `src/orchestrator.ts`  | Phases, planning, parallel execution, 429/5xx retries         |
| `src/agents.ts`        | Agent construction, tools (website, commands, Jira)           |
| `src/skill.ts`         | Loading and parsing skills, keyword-based selection           |
| `src/model.ts`         | OpenAI-compatible API client                                  |
| `src/fetcher.ts`       | Fetching and cleaning page content                            |
| `src/config.ts`        | Configuration from environment variables                      |
| `src/types.ts`         | Shared types                                                  |

Stack: TypeScript, `@openai/agents` (agents and tools), `openai` (client),
`zod` (tool schemas), `dotenv`.

## Error resilience

- Retries on `429` and `5xx` with exponential backoff (up to 8 attempts), honoring
  `Retry-After`.
- A delay between model calls to stay within requests-per-minute limits.
- A failed phase does not crash the run: it is recorded as `[ERR]`, work continues, and
  reports are still saved.
